# 7. 대용량 트래픽 / 성능 최적화

## 기본 ⭐

- 처리량(throughput)과 지연시간(latency)의 차이는? p99 latency를 왜 보나요?
- 수평 확장(scale-out)과 수직 확장(scale-up)의 차이와 각각의 한계는?
- 로드밸런서의 역할과 알고리즘(round robin, least connection)을 설명해주세요.
- Stateless 서버 설계가 왜 확장에 유리한가요? 세션은 어떻게 처리하나요?
- CDN은 무엇이고 언제 효과적인가요? (웹툰 이미지 서빙 관점에서)

## 중급 ⭐⭐

- API 응답이 갑자기 느려졌습니다. 병목 지점을 찾는 과정을 처음부터 끝까지 설명해주세요. (모니터링 → 프로파일링)
- 부하 테스트는 어떻게 설계하나요? 목표 TPS 산정, 시나리오, 도구 경험을 말해주세요.
- Rate limiting 알고리즘(token bucket, sliding window)을 비교해주세요. 분산 환경에서는 어떻게 구현하나요?
- 서킷 브레이커 패턴이란? open/half-open/closed 상태 전이와 설정값 튜닝 기준은?
- 타임아웃은 어디에(connection/read/전체) 어떤 기준으로 설정하나요? 타임아웃 없는 외부 호출의 위험은?
- 재시도(retry)를 잘못 설계하면 장애를 증폭시키는 이유는? (retry storm, exponential backoff + jitter)
- 대량의 푸시/알림 발송을 어떻게 설계하나요?
- 인기 웹툰 신작 공개 시각(예: 밤 11시)에 트래픽이 스파이크됩니다. 어떤 계층에서 어떻게 대비하나요?

## 고난이도 ⭐⭐⭐

- 특정 시각 선착순 이벤트(티켓팅급 트래픽)를 위한 대기열 시스템을 설계해보세요.
- 갑작스러운 장애 상황에서 "부분 기능 저하(graceful degradation)"를 어떻게 설계하나요? 예를 들어 추천 시스템이 죽었을 때 서비스는 어떻게 동작해야 하나요?
- 백프레셔(backpressure)란 무엇이고, 시스템의 어떤 지점들에 필요한가요?
- 커넥션 풀, 스레드풀, 큐 크기 등 자원 한계 설정과 Little's Law의 관계를 설명해주세요.
- 하나의 느린 다운스트림 서비스가 전체 시스템을 마비시키는 cascading failure의 메커니즘과 방어 계층(bulkhead 등)을 설명해주세요.
- 조회수/좋아요 집계를 실시간에 가깝게 보여주되 DB 부하를 최소화하는 파이프라인을 설계해보세요.
- 글로벌 서비스(멀티 리전)에서 데이터 지역성, 지연시간, 정합성 사이의 트레이드오프를 어떻게 다루나요?

## 알면 좋은 +α

- Load shedding이란? 과부하 시 어떤 요청부터, 어디서 버리나요?
- 오토스케일링 지표로 CPU 사용률이 부적합한 경우는? 대안 지표는 무엇인가요?
- 부하 테스트 결과가 운영과 다르게 나오는 원인들은 무엇인가요?
