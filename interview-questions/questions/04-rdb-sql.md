# 4. RDB / SQL / 데이터 모델링

## 기본 ⭐

- 인덱스는 어떻게 동작하나요? B+Tree 구조를 설명해주세요.
- 인덱스를 걸었는데도 풀스캔이 발생하는 경우는 어떤 경우인가요?
- 클러스터드 인덱스와 논클러스터드(세컨더리) 인덱스의 차이는? (InnoDB 기준)
- 정규화와 반정규화란? 반정규화를 선택하는 기준은?
- 트랜잭션의 ACID를 설명해주세요.
- JOIN의 종류(INNER, LEFT, ...)와 실행 방식(NL, Hash, Sort-merge)을 설명해주세요.
- `WHERE`절과 `HAVING`절의 차이는?

## 중급 ⭐⭐

- 복합 인덱스의 컬럼 순서는 어떤 기준으로 정하나요? 카디널리티와의 관계는?
- 커버링 인덱스란? 어떤 상황에서 효과가 큰가요?
- 실행 계획(EXPLAIN)을 어떻게 읽나요? 느린 쿼리를 발견했을 때의 개선 프로세스를 설명해주세요.
- MVCC란 무엇인가요? InnoDB에서 어떻게 구현되어 있나요?
- 갭 락(gap lock), 넥스트 키 락이란? 어떤 상황에서 데드락을 유발하나요?
- `LIMIT 100000, 20` 같은 깊은 페이지네이션이 느린 이유와 해결책(no-offset, 커서 기반)은?
- 대용량 테이블에 컬럼 추가/인덱스 추가를 무중단으로 하려면? (online DDL, pt-osc 등)
- DB 커넥션 수와 처리량(throughput)의 관계 — 커넥션을 늘리면 항상 빨라지나요?
- 긴 트랜잭션(long transaction)은 DB에 어떤 해악을 끼치나요? 애플리케이션에서 트랜잭션을 짧게 유지하는 방법은?
- 목록 API의 전체 건수(total count) 조회가 대용량에서 비싼 이유와 대안은? (근사치, 카운트 캐싱, 무한 스크롤 전환)
- RDB의 JSON 컬럼은 언제 쓰고 언제 피하나요? 인덱싱과 스키마 진화 관점의 트레이드오프는?
- `SELECT ... FOR UPDATE`는 어떤 락을 잡나요? WHERE 조건이 인덱스를 못 타면 무슨 일이 벌어지나요?
- `LIKE '%keyword%'` 검색이 인덱스를 못 타는 이유는? 풀텍스트 인덱스와 검색 엔진(Elasticsearch) 전환은 어떤 기준으로 판단하나요?
- 대시보드용 통계 조회가 운영 트래픽과 같은 DB를 때리고 있습니다. 어떻게 분리하나요? (집계 테이블, 사전 계산 배치, replica)
- 배포도 없었는데 어제부터 DB CPU만 올랐습니다. "변경이 없다"는 전제를 어떻게 검증하고, 원인 후보를 어떻게 좁혀가나요?

## 고난이도 ⭐⭐⭐

- 웹툰 에피소드 조회수 같은 초고빈도 카운터 갱신을 RDB에 직접 하면 어떤 문제가 있나요? 어떻게 설계하겠습니까?
- 샤딩이 필요한 시점은 언제이고, 샤드 키 선정 기준은? 크로스 샤드 조회/트랜잭션은 어떻게 다루나요?
- 수억 건 테이블에서 특정 기간 데이터를 삭제/아카이빙해야 합니다. 어떻게 접근하겠습니까? (파티셔닝 포함)
- 유니크 채번(주문번호 등)을 대용량 트래픽에서 어떻게 설계하나요? (Auto Increment 한계, Snowflake, 채번 테이블, UUID v7 비교)
- "결제는 성공했는데 주문 데이터가 없다"는 정합성 문제가 발생했습니다. 원인 후보와 재발 방지 설계를 설명해주세요.
- DB 장애로 failover가 일어나는 동안 애플리케이션은 어떻게 동작해야 하나요?
