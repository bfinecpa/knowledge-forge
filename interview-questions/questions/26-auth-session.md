# 26. 인증 / 인가 / 세션 (이력 기반 심화)

> 이력서에 IAM·인증 도메인 경력이 있으면 면접관은 반드시 이 영역을 파고든다. 가장 깊게 답해야 하는 홈그라운드이자, 콘텐츠 플랫폼의 계정·세션·기기 제한 기능과 직결되는 영역이다.

## 기본 ⭐

- 대규모 서비스의 로그인 세션 저장소를 설계해보세요. 세션 클러스터링, 중앙 저장소(Redis), 토큰 방식의 트레이드오프는?
- SSO(Single Sign-On)의 동작 원리를 설명해주세요. SAML과 OIDC는 무엇이 다르고 각각 언제 쓰나요?
- 인가 모델 RBAC과 ABAC의 차이는? 조직 계층(회사-부서-팀)이 있는 서비스의 권한 설계는 어떻게 하나요?

## 중급 ⭐⭐

- 동시 로그인 제한(기기 수 제한, 중복 로그인 차단)을 어떻게 구현하나요? 정확성과 사용자 경험의 균형은 어디서 잡나요?
- "로그아웃하면 토큰이 즉시 무효화되어야 한다"는 요구를 JWT 기반 시스템에서 어떻게 구현하나요? 그렇게 하고 나면 JWT의 장점은 얼마나 남나요?
- 멀티테넌트 서비스에서 테넌트 간 데이터 격리 방식들(DB 분리, 스키마 분리, 로우 레벨 격리)과 선택 기준은?
- 계정 탈취 대응으로 "모든 기기에서 로그아웃" 기능을 어떻게 구현하나요?
- 외부 IdP(고객사 AD/LDAP, 소셜 로그인)에 장애나 응답 지연이 발생하면 로그인 흐름은 어떻게 동작해야 하나요?
- 웹 클라이언트에서 토큰을 어디에 저장해야 하나요? (httpOnly 쿠키 vs localStorage) XSS/CSRF 관점의 트레이드오프는?

## 고난이도 ⭐⭐⭐

- 수만 개 테넌트가 쓰는 B2B 서비스에서 고객사의 대규모 조직 개편(수천 명 입사/퇴사/부서 이동)을 동기화하는 시스템을 설계해보세요. (SCIM, 배치 vs 이벤트, 부분 실패 복구)
- 인증 시스템은 전 서비스의 SPOF입니다. 인증 서버 장애 시에도 서비스 영향을 최소화하는 설계는? (토큰 검증의 로컬화, 공개키 캐싱, 만료 유예)
- 권한 변경(퇴사, 권한 회수)이 이미 발급된 세션/토큰에 반영되기까지의 지연을 어떻게 다루나요? 즉시 반영이 꼭 필요한 지점과 그 비용은?

## 알면 좋은 +α

- OAuth의 client credentials, device code 등 authorization code 외의 grant는 각각 어떤 상황을 위한 것인가요?
- 로그인에 크리덴셜 스터핑이 들어올 때 계정 잠금 정책의 딜레마(공격자가 잠금을 역이용한 DoS)는 어떻게 푸나요?
- 인증/인가 감사 로그는 무엇을 남겨야 하고, 일반 로그와 요구 수준이 어떻게 다른가요?
- 패스키(WebAuthn) 같은 패스워드리스 인증에서 백엔드가 관리해야 하는 것들은? 비밀번호 방식 대비 무엇이 사라지고 무엇이 새로 생기나요?
