# 22. 글로벌 서비스 / 국제화 (시간, 인코딩, 규제)

## 기본 ⭐

- 서버에서 시간을 저장·처리할 때의 원칙은 무엇인가요? `Instant`, `LocalDateTime`, `ZonedDateTime`은 각각 언제 쓰나요?
- MySQL의 utf8과 utf8mb4의 차이는? 이모지가 포함된 댓글을 저장하면 무슨 일이 벌어지나요?
- 다국어 메시지(에러 메시지, 알림 문구)는 서버와 클라이언트 중 어디서 번역해야 하나요? 그 선택이 API 설계에 어떤 영향을 주나요?

## 중급 ⭐⭐

- "매일 밤 11시 신작 공개"를 여러 국가에 서비스한다면 공개 시각 처리를 어떻게 설계하나요? DST(서머타임) 전환일에는 어떤 문제가 생기나요?
- 국가별 콘텐츠 노출 제한(geo-blocking)을 구현해보세요. 사용자의 국가는 무엇으로 판정하고, 각 판정 수단의 한계는 무엇인가요?
- 국가별 일 단위 랭킹/정산에서 "하루"의 기준은 어떻게 정의하나요? 정의하지 않으면 어떤 문제가 생기나요?
- 국가별로 통화, 소수점 자리, 반올림 규칙이 다를 때 가격 데이터 모델을 어떻게 설계하나요?

## 고난이도 ⭐⭐⭐

- 성인 인증 방식과 연령 기준이 국가마다 다릅니다. 국가별 분기(if-else)가 코드 전체에 퍼지지 않게 하려면 어떻게 설계하나요?
- 특정 국가의 데이터 국외 이전 제한 규제 하에서 "전체 국가 통합 통계"를 제공해야 한다면 어떻게 접근하나요?
- 법정 보존 의무(거래 기록 5년 보관)와 개인정보 삭제 요구(GDPR 삭제권)가 같은 데이터에 동시에 걸릴 때 어떻게 설계하나요?

## 알면 좋은 +α

- 번역이 아직 없는 언어/문구는 어떻게 폴백하나요?
- 국가마다 수집 가능한 개인정보 항목과 동의 방식이 다를 때 회원 데이터 모델을 어떻게 설계하나요?
- 타임존 데이터베이스(tzdata)가 변경되면(어느 국가의 DST 폐지 등) 시스템에 어떤 영향이 있나요? 저장된 미래 예약 시각은 어떻게 되나요?
